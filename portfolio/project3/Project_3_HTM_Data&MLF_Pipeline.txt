Project 3: High-Throughput Market Data & ML Feature Pipeline 명세서
본 프로젝트는 어떠한 마케팅이나 외부 확장 이전에, 펀드의 수익 창출(Alpha)을 책임질 모델이 오차 없이 작동할 수 있도록 완벽한 성능의 데이터 인프라를 확립하는 작업입니다. 초고빈도(HFT) 호가 데이터와 온체인 이벤트를 유실 없이 수집하고, 머신러닝(ML) 모델이 즉각적으로 추론할 수 있는 피처(Feature)로 가공하여 전달하는 실시간 파이프라인을 구축합니다.

1. System Overview & Architecture
목표: CEX(중앙화 거래소) 및 DEX(탈중앙화 거래소)의 스트리밍 데이터를 마이크로초 단위로 가공하여 고빈도 트레이딩 피처(OFI, Micro-price 등)를 생성하고, 이를 ML 추론 서버로 지연 없이 전달.

개발 환경 및 언어 스택:

Ingestion & Feature Engine: Rust (Tokio 비동기 런타임 기반 네트워크 I/O 최적화)

Message Broker (IPC): ZeroMQ (인메모리 브로드캐스팅) 또는 FlatBuffers (직렬화 오버헤드 최소화)

ML Inference (Consumer): Python 3.10+ (ONNX Runtime, TensorRT)

3. System-Level Optimization (엔지니어링 차별화 포인트)
단순한 API 호출 스크립트가 아닌, 대용량 분산 처리 시스템의 코어 엔지니어로 어필할 수 있는 최적화 기법입니다.

Zero-Copy Serialization:

데이터를 JSON 포맷으로 파싱하고 직렬화하는 과정은 HFT 환경에서 치명적인 병목입니다. 데이터를 고정 크기의 C 구조체 형태나 FlatBuffers로 패킹하여 네트워크 소켓에 바로 밀어 넣고, Python에서 바이트(Byte) 단위로 바로 캐스팅하여 읽도록 설계합니다.

Asynchronous I/O without Thread Blocking:

Rust의 epoll 기반 비동기 런타임을 활용해 수백 개의 웹소켓 커넥션을 단일 스레드 내에서 블로킹 없이 처리합니다.

Pre-allocated Memory for Feature Windows:

이동 평균이나 OFI를 계산할 때 매번 메모리를 할당하는 덱(Deque) 대신, 사전 할당된 원형 배열(Circular Array)을 사용하여 가비지 컬렉션(GC)이나 메모리 파편화를 원천 차단합니다.

4. Core Implementation (Rust Data & Feature Pipeline)
Rust 코어는 데이터를 수신하고 피처를 연산한 뒤, ZeroMQ를 통해 파이썬으로 브로드캐스팅합니다.

// Rust: Async Data Ingestion and Feature Calculation (Producer)

use std::sync::Arc;
use tokio::net::TcpStream;
// Assume tokio-tungstenite and zmq crates are available
// use tokio_tungstenite::{connect_async, tungstenite::protocol::Message};

#[repr(C)]
pub struct MLFeatureVector {
    pub timestamp: u64,
    pub micro_price: f64,
    pub order_flow_imbalance: f64,
}

pub struct FeatureEngine {
    // Internal state for rolling calculations
    bid_volume_prev: f64,
    ask_volume_prev: f64,
}

impl FeatureEngine {
    pub fn update_and_calculate(&mut self, current_bid_vol: f64, current_ask_vol: f64) -> f64 {
        // Calculate Order Flow Imbalance (OFI)
        let bid_change = current_bid_vol - self.bid_volume_prev;
        let ask_change = current_ask_vol - self.ask_volume_prev;
        
        self.bid_volume_prev = current_bid_vol;
        self.ask_volume_prev = current_ask_vol;
        
        bid_change - ask_change
    }
}

pub async fn run_pipeline() {
    // Initialize ZeroMQ Publisher
    let context = zmq::Context::new();
    let publisher = context.socket(zmq::PUB).unwrap();
    publisher.bind("tcp://127.0.0.1:5555").expect("Failed to bind ZeroMQ");

    let mut engine = FeatureEngine { bid_volume_prev: 0.0, ask_volume_prev: 0.0 };

    // Async loop receiving data from WebSocket (pseudo-logic for brevity)
    loop {
        // let raw_data = websocket.next().await...
        
        // Mock extracted data
        let current_time = 1710000000000; 
        let micro_price = 50000.50;
        let ofi = engine.update_and_calculate(10.5, 8.2);

        let feature = MLFeatureVector {
            timestamp: current_time,
            micro_price,
            order_flow_imbalance: ofi,
        };

        // Zero-copy cast struct to bytes and publish
        unsafe {
            let byte_ptr = &feature as *const MLFeatureVector as *const u8;
            let byte_slice = std::slice::from_raw_parts(byte_ptr, std::mem::size_of::<MLFeatureVector>());
            publisher.send(byte_slice, 0).unwrap();
        }
    }
}
