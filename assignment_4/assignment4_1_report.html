1설계 개요

1.1 설계 목표

이 보고서는 Assignment #4-2에서 구현할 도서관 관리 웹 애플리케이션의 데이터베이스 스키마를 설계한 결과다. 설계는 다음 세 가지를 목표로 했다.

  • 기능 완전성 — 명세의 필수 기능(로그인·회원가입, 서적 검색·정렬, 대출·반납, 인기 서적 차트, 관리자의 서적·카테고리·회원 관리)과 추가 기능 4가지가 필요로 하는 데이터를 모두 표현한다.
  • 정규화 — 모든 릴레이션을 BCNF로 유지해 같은 사실이 두 곳에 저장되지 않게 하고, 갱신·삽입·삭제 이상을 막는다.
  • DB 수준의 무결성 — 규칙은 가능한 한 PK·FK·UNIQUE·CHECK·부분 유일 인덱스로 DB가 직접 강제하게 하고, 여러 행을 함께 보아야 판단할 수 있는 규칙(대출 한도, 연체 여부 등)만 애플리케이션이 하나의 트랜잭션 안에서 검사한다.

1.3 핵심 설계 결정

① 서적(Book)과 실물 복본(BookCopy)의 분리

명세는 "동일한 책이 여러 권 있을 수 있고, 차트는 이를 합산하며, 대출 기록에서는 그중 정확히 어느 책을 빌렸는지 알 수 있어야 한다"고 요구한다. 그래서 제목·저자 같은 서지 정보는 Book에 한 번만 두고, 실물 한 권마다 BookCopy 한 행을 둔다. 차트는 Book 단위로 집계하고, 대출은 BookCopy를 참조한다.

② 대출(Loan)을 독립 Entity로 모델링

같은 회원이 같은 복본을 시기를 달리해 여러 번 빌릴 수 있으므로, (회원, 복본) 쌍으로는 대출 한 건을 식별할 수 없다. 따라서 대출을 관계 집합이 아닌 대리키 loan_id를 가진 Entity로 두고, return_date IS NULL인 행을 "현재 대출 중"으로 해석한다.

③ 저자(Author) 분리

저자명을 Book에 문자열로 반복 저장하면 표기를 고칠 때 갱신 이상이 생긴다. 서적 추가 화면도 기존 저자를 고르거나 새 저자를 입력하는 방식이고, 인기 저자 차트는 author_id로 집계한다. 한 책의 저자는 한 명으로 정의했다(N:1).

④ 카테고리의 다대다(M:N) 관계

"책은 동시에 여러 카테고리에 속할 수 있다"는 요구를 교차 릴레이션 Book_Category로 해소했다. 카테고리를 삭제하면 연결 행만 함께 지워지므로 서적은 나머지 카테고리를 그대로 유지한다.

⑤ 무결성은 먼저 DB 제약으로 보장

"대출 중인 복본은 다시 빌릴 수 없다"는 규칙은 Loan(copy_id) WHERE return_date IS NULL 부분 유일 인덱스로, "같은 책에 대기 중인 예약은 1건만"이라는 규칙은 Reservation(user_id, book_id) WHERE status = 'waiting' 부분 유일 인덱스로 강제한다. 별점 범위, 상태 값, 날짜 순서, 로그인 ID 형식은 CHECK로 막는다. 애플리케이션 버그나 동시 요청이 있어도 DB가 잘못된 상태를 거부한다.

2Entity 설계: 역할과 필요성

각 Entity의 역할과 필요성, 그리고 릴레이션으로 옮겼을 때의 속성·타입·제약조건을 함께 정리했다. 밑줄은 기본키(PK), 기울임은 외래키(FK)다. 모든 Entity의 기본키는 SERIAL 대리키이고, 로그인 ID를 그대로 쓰는 Users만 자연키를 쓴다.

Users회원 · 관리자 계정핵심

역할 일반 회원(user)과 관리자(admin) 계정의 인증 정보와 권한을 저장한다.

필요성 ID·비밀번호 로그인, 권한에 따른 기능 분리(관리자만 서적·카테고리·회원 관리), 그리고 대출·리뷰·예약을 누가 했는지 식별하는 기준이다. 관리자 가입 코드(학번 2022065250)는 가입 시점에만 검증하고 저장하지 않는다. 저장하면 모든 관리자 행에 같은 값이 반복될 뿐 새로운 정보가 없기 때문이다.

속성타입제약조건설명
user_idVARCHAR(20)PK, CHECK ~ '^[A-Za-z0-9_]{3,20}$'로그인 ID. 화면에 그대로 출력되므로 영문·숫자·밑줄로 제한
password_hashVARCHAR(255)NOT NULLsalt를 포함한 scrypt 해시. 평문 비밀번호는 저장하지 않음
nameVARCHAR(50)NULL 허용이름 (가입 시 선택 입력)
emailVARCHAR(100)UNIQUE, NULL 허용이메일 (선택 입력, 입력하면 중복 불가)
roleVARCHAR(10)NOT NULL, DEFAULT 'user', CHECK IN ('user', 'admin')권한
created_atTIMESTAMPNOT NULL, DEFAULT now()가입 일시

역할 저자명을 한 곳에 저장하고 Book이 author_id로 참조한다.

필요성 저자명 중복 저장에 따른 갱신 이상을 막고, 서적 추가 시 저자 선택·신규 등록과 저자 검색·정렬, 인기 저자 차트 집계의 기준이 된다.

Book서적 (서지 정보)핵심

역할 한 종류의 책에 대한 서지 정보(제목·저자·출판사·ISBN 등)를 한 행에 저장한다. 같은 책을 여러 권 소장해도 Book 행은 하나다.

필요성 서적 목록의 제목·저자·카테고리 표시와 검색·정렬, "같은 책 2권 동시 대출 불가" 판정, 인기 서적 차트의 집계 단위가 모두 이 Entity다.

속성타입제약조건설명
book_idSERIALPK서적 식별자

BookCopy실물 복본 (개별 도서)핵심

역할 도서관이 가진 실물 책 한 권 한 권을 나타낸다. 어떤 Book의 복본인지, 청구기호, 현재 상태를 저장한다.

필요성 "대출 기록에서 동일한 책 중 정확히 어느 책을 빌렸는지 확인"하려면 실물 단위의 식별자가 있어야 한다. 서적 목록의 총 수량(COUNT(copy_id))과 대출 가능 수량(status = 'available'인 복본 수)도 여기서 계산한다.

속성타입제약조건설명

Category카테고리핵심

역할 도서 분류 체계(소설, 과학, 컴퓨터 등)의 이름과 설명을 저장한다.

필요성 관리자가 서적과 무관하게 카테고리를 추가·삭제할 수 있어야 하고, 카테고리별 검색과 카테고리별 인기 차트의 기준이 된다. 서적과는 Book_Category를 통해 연결된다.

속성타입제약조건설명

Book_Category서적–카테고리 연결 (교차 릴레이션)핵심

역할 다대다 관계 Belongs_To를 릴레이션으로 옮긴 것이다. 행 하나가 "서적 b는 카테고리 c에 속한다"는 사실 하나를 나타낸다.

필요성 한 서적이 여러 카테고리에 속하려면 연결을 별도 행으로 저장해야 한다. 두 FK 모두 CASCADE이므로 서적이나 카테고리가 삭제되면 연결만 사라진다.

속성타입제약조건설명

category_idINTEGERPK, FK → Category ON DELETE CASCADE
Loan대출 · 반납 기록핵심

역할 한 회원이 한 복본을 빌린 대출 한 건을 기록한다. 대출일, 반납 기한, 실제 반납일을 저장하며 return_date가 NULL이면 아직 대출 중이다.

필요성 현재 대출 상태, 1인 최대 3권 제한, 같은 책 중복 대출 금지, 연체 판정, 회원별 대출 기록(복본 번호 포함), 최근 3개월 인기 차트가 모두 이 기록에서 나온다. 대출 기간은 7일이며, 대출 시 due_date = loan_date + 7로 저장한다.

속성타입제약조건설명
loan_idSERIALPK대출 식별자 (반납 요청의 대상)
user_idVARCHAR(20)NOT NULL, FK → Users ON DELETE RESTRICT대출한 회원
copy_idINTEGERNOT NULL, FK → BookCopy ON DELETE CASCADE대출한 복본 (정확히 어느 책인지)
loan_dateDATENOT NULL, DEFAULT CURRENT_DATE대출일
due_dateDATENOT NULL, CHECK (due_date > loan_date)반납 기한. 이 날짜가 되면 연체
return_dateDATENULL 허용, CHECK (return_date >= loan_date)반납일. NULL이면 대출 중

부분 유일 인덱스 UNIQUE (copy_id) WHERE return_date IS NULL — 한 복본에 미반납 대출이 두 건 이상 존재할 수 없다.

Review도서 리뷰 · 별점확장

역할 회원이 서적에 남긴 1~5점 별점과 서평을 저장한다. 리뷰는 실물 복본이 아닌 책의 내용에 대한 평가이므로 Book을 참조한다.

필요성 추가 기능 E1(리뷰)과 통계 S1(평점 통계)의 데이터 원천이다. UNIQUE (user_id, book_id)로 한 회원이 한 책에 리뷰를 하나만 남기게 해 평점 조작을 막는다.

속성타입제약조건설명
review_idSERIALPK리뷰 식별자
user_idVARCHAR(20)NOT NULL, FK → Users ON DELETE RESTRICT작성자와 대상 서적. (user_id, book_id) UNIQUE
book_idINTEGERNOT NULL, FK → Book ON DELETE CASCADE
ratingSMALLINTNOT NULL, CHECK (rating BETWEEN 1 AND 5)별점
commentTEXTNULL 허용서평
created_atTIMESTAMPNOT NULL, DEFAULT now()작성 일시
Reservation대출 예약 대기열확장

역할 모든 복본이 대출 중인 서적에 회원이 걸어 둔 예약을 저장한다. 특정 복본이 아니라 "그 책 중 먼저 반납되는 아무 복본"을 기다리는 것이므로 Book을 참조한다.

필요성 추가 기능 E2(예약)의 대기 순서(reserved_at)와 상태를 관리한다. 같은 회원이 시기를 달리해 같은 책을 다시 예약할 수 있으므로 대리키를 쓰고, 대기 중인 예약의 중복만 부분 유일 인덱스로 막는다.

속성타입제약조건설명
reservation_idSERIALPK예약 식별자
user_idVARCHAR(20)NOT NULL, FK → Users ON DELETE RESTRICT예약한 회원
book_idINTEGERNOT NULL, FK → Book ON DELETE CASCADE예약 대상 서적
statusVARCHAR(10)NOT NULL, DEFAULT 'waiting', CHECK IN ('waiting', 'fulfilled', 'cancelled')대기 / 대출로 이어짐 / 취소
reserved_atTIMESTAMPNOT NULL, DEFAULT now()예약 시각 (대기 순서의 기준)

부분 유일 인덱스 UNIQUE (user_id, book_id) WHERE status = 'waiting' — 한 회원이 같은 책에 대기 중인 예약을 두 건 가질 수 없다.

3Relationship 설계: 관계와 그 이유

Entity 사이의 관계 집합은 9개다. 대응수(cardinality)와 함께 각 Entity의 참여 제약(participation)을 정의했다. 전체 참여는 그 Entity의 모든 행이 반드시 관계에 참여해야 한다는 뜻으로, 릴레이션에서는 NOT NULL 외래키가 된다. 1:N 관계는 N쪽 릴레이션의 외래키로, M:N 관계는 교차 릴레이션으로 변환했다.

관계연결 · 대응수참여릴레이션 변환의미와 필요성
Has_CopyBook 1 : N BookCopyBook 전체
BookCopy 전체		BookCopy.book_id한 서적은 여러 복본을 가지며, 모든 복본은 정확히 한 서적에 속한다. 동일 도서 다중 소장과 차트의 복본 합산을 함께 가능하게 한다. Book 쪽 전체 참여는 애플리케이션이 보장한다(서적 추가 시 수량 1 이상, 마지막 복본을 삭제하면 서적도 삭제).
Written_ByBook N : 1 AuthorBook 전체
Author 부분		Book.author_id모든 서적은 저자 한 명을 가지고, 한 저자는 여러 서적을 쓸 수 있다. 저자명을 한 곳에만 저장하며 인기 저자 차트의 집계 기준이 된다.
Belongs_ToBook M : N CategoryBook 부분
Category 부분		Book_Category한 서적은 여러 카테고리에, 한 카테고리에는 여러 서적이 속한다. 관리자가 빈 카테고리를 먼저 만들 수 있으므로 양쪽 모두 부분 참여다.
BorrowsUsers 1 : N LoanUsers 부분
Loan 전체		Loan.user_id회원 한 명이 여러 건을 대출한다. 대출 한도(3권), 연체 여부, 회원별 대출 기록을 회원 단위로 조회하는 근거다.
Borrowed_InBookCopy 1 : N LoanBookCopy 부분
Loan 전체		Loan.copy_id한 복본은 시기를 달리해 여러 번 대출된다. 대출이 Book이 아닌 BookCopy와 연결되므로 같은 책 중 정확히 어느 복본을 빌렸는지 기록된다.
WritesUsers 1 : N ReviewUsers 부분
Review 전체		Review.user_id회원은 여러 서적에 리뷰를 남길 수 있다. 리뷰 작성 자격(해당 서적 대출 이력)을 확인하는 기준이다.
EvaluatesBook 1 : N ReviewBook 부분
Review 전체		Review.book_id한 서적은 여러 회원의 리뷰를 받는다. 서적별·카테고리별 평점 통계의 집계 경로다.
RequestsUsers 1 : N ReservationUsers 부분

TargetsBook 1 : N ReservationBook 부분

Loan · Review · Reservation을 Entity로 둔 이유. 세 가지 모두 두 Entity를 잇는 관계처럼 보이지만, 관계 집합의 한 원소는 참여 Entity의 키 조합으로 식별되어야 한다. 같은 회원이 같은 복본을 여러 번 빌리고(Loan), 같은 책을 취소 후 다시 예약하므로(Reservation) 키 조합만으로는 한 건을 구분할 수 없다. 그래서 각각 대리키를 가진 Entity로 모델링하고 양쪽과 1:N 관계를 맺게 했다. Review는 (회원, 서적) 조합이 유일하지만, 다른 두 이력 Entity와 구조를 맞추고 리뷰 수정·삭제 요청을 review_id 하나로 가리키기 위해 같은 방식을 택했다.

6.1 대출 트랜잭션

대출 규칙은 여러 행을 함께 보아야 하므로 하나의 트랜잭션에서 검사한다. 복본 행을 먼저 잠가 같은 복본에 대한 동시 요청을 직렬화한다.

BEGIN;
SELECT book_id, status FROM BookCopy WHERE copy_id = $1 FOR UPDATE;   -- status = 'available' 이어야 함

SELECT COUNT(*)                                           AS open_loans,    -- 3 미만
       COUNT(*) FILTER (WHERE CURRENT_DATE >= l.due_date) AS overdue,       -- 0 이어야 함
       COUNT(*) FILTER (WHERE c.book_id = $3)             AS same_book      -- 0 이어야 함
  FROM Loan l JOIN BookCopy c ON c.copy_id = l.copy_id
 WHERE l.user_id = $2 AND l.return_date IS NULL;

-- 대기 중인 예약이 있으면 가장 먼저 예약한 회원만 대출 가능 (추가 기능 E2)
INSERT INTO Loan (user_id, copy_id, loan_date, due_date)
VALUES ($2, $1, CURRENT_DATE, CURRENT_DATE + 7);
UPDATE BookCopy SET status = 'borrowed' WHERE copy_id = $1;
COMMIT;

6.2 최근 3개월 인기 서적 차트

SELECT b.title, a.author_name, COUNT(*) AS borrow_count
  FROM Loan l
  JOIN BookCopy c ON c.copy_id   = l.copy_id
  JOIN Book b     ON b.book_id   = c.book_id
  JOIN Author a   ON a.author_id = b.author_id
 WHERE l.loan_date >= CURRENT_DATE - INTERVAL '3 months'
-- 카테고리별 차트는 여기에 조건 하나를 더한다:
--   AND EXISTS (SELECT 1 FROM Book_Category bc
--               WHERE bc.book_id = b.book_id AND bc.category_id = $1)
 GROUP BY b.book_id, b.title, a.author_name
 ORDER BY borrow_count DESC
 LIMIT 10;

7추가 기능 설계

명세는 "명세 외 기능 3가지 이상, 그중 통계 기능은 정확히 2가지"를 요구한다. 이에 따라 비통계 기능 2가지(E1, E2)와 통계 기능 2가지(S1, S2), 모두 4가지를 설계했다. 통계가 2가지를 넘지 않도록, 이 두 기능 외의 화면에는 평균·순위 같은 집계 지표를 추가하지 않는다. 인기 서적·저자 차트는 필수 기능이므로 여기에 포함하지 않는다.

E1

도서 리뷰 및 별점

비통계 기능 · Review
목적
대출 횟수만으로는 알 수 없는 책의 내용과 난이도에 대한 평가를 회원끼리 공유한다.
동작
서적 상세 페이지에 리뷰 목록과 평균 별점을 보여 준다. 그 서적을 한 번이라도 대출한 회원만 리뷰를 쓸 수 있고(Loan ⋈ BookCopy로 확인), 회원당 서적별 리뷰는 하나다. 작성자는 자기 리뷰를 수정·삭제할 수 있다.
스키마
Review의 UNIQUE (user_id, book_id)와 CHECK (rating BETWEEN 1 AND 5)가 중복 리뷰와 잘못된 별점을 막는다.
E2

대출 예약 대기열

비통계 기능 · Reservation
목적
모든 복본이 대출 중인 인기 도서를 기다리는 회원에게 순서를 보장해, 반납 시점을 노려 계속 새로고침해야 하는 불편을 없앤다.
동작
대출 가능한 복본이 없고, 그 책을 대출 중이 아니며, 대기 중인 예약도 없을 때 예약할 수 있다. 대기 예약이 있는 동안 반납된 복본은 가장 먼저 예약한 회원(reserved_at 최솟값)만 대출할 수 있고, 그 회원이 대출하면 예약은 fulfilled가 된다. 회원은 자기 예약을 취소(cancelled)할 수 있다.

부분 유일 인덱스 (user_id, book_id) WHERE status = 'waiting'가 중복 대기를 막고, 대기 순번은 reserved_at으로 정한다.
S1

통계 기능 1/2 · Review Book Book_Category Category
목적

내용
① 서적별 평균 별점과 리뷰 수 ② 카테고리별 평균 별점, 리뷰 수, 그리고 가장 평점이 높은 서적. 별도의 통계 테이블 없이 Review에서 매번 집계하므로 원본 데이터와 항상 일치한다.
SELECT c.category_name,
       COUNT(r.review_id)      AS review_count,
       ROUND(AVG(r.rating), 2) AS avg_rating
  FROM Category c
  JOIN Book_Category bc ON bc.category_id = c.category_id
  LEFT JOIN Review r    ON r.book_id      = bc.book_id
 GROUP BY c.category_id, c.category_name
 ORDER BY avg_rating DESC NULLS LAST;
S2

월별 대출 · 연체 통계와 이용자 독서 통계

통계 기능 2/2 · Loan Users
목적
관리자에게는 도서관 운영 지표를, 회원에게는 자신의 독서 습관을 보여 준다.
내용
① 월별 대출 건수와 연체율 (관리자) ② 회원별 누적 대출 수 순위, 즉 다독 순위 (다른 회원의 기록이 드러나므로 관리자 전용) ③ 본인의 누적 대출 수와 기한 내 반납률 (모든 회원). 반납일이 기한 이후이거나(return_date >= due_date), 아직 반납하지 않았는데 기한이 지난 대출을 연체로 본다.
SELECT to_char(loan_date, 'YYYY-MM') AS month,
       COUNT(*)                       AS loans,
       ROUND(100.0 * COUNT(*) FILTER (WHERE COALESCE(return_date, CURRENT_DATE) >= due_date)
             / COUNT(*), 1)           AS overdue_rate_pct
  FROM Loan
 GROUP BY month
 ORDER BY month DESC;

8설계 검토: 정규화와 트레이드오프

8.1 정규화

모든 릴레이션에서 비자명 함수 종속의 결정자는 후보키뿐이므로 BCNF를 만족한다. 예를 들어 Book에서는 book_id와 후보키 isbn만 다른 속성을 결정하고, 저자명은 Author로 분리되어 author_id → author_name 같은 이행 종속이 남지 않는다. Book_Category는 모든 속성이 키인 릴레이션이다.

Loan.due_date는 현재 규칙으로는 loan_date + 7이지만, 대출 시점의 정책으로 정해진 기한이라는 별개의 사실로 보아 저장한다. 대출 기간 정책이 바뀌거나 기한을 연장해도 과거 기록의 기한은 그대로여야 하므로 loan_date → due_date는 성립하는 종속이 아니다. 그래서 CHECK도 등식이 아닌 due_date > loan_date로 두었다.

8.2 의도적인 트레이드오프

결정얻는 것대가와 대응
BookCopy.status 유지'maintenance'처럼 Loan으로 표현할 수 없는 상태를 담고, 서적 목록의 대출 가능 수량을 Loan 조인 없이 계산한다.'borrowed' 여부는 미반납 Loan과 중복된다. 대출·반납 트랜잭션에서 두 테이블을 함께 갱신하고, 부분 유일 인덱스가 이중 대출을 최종 차단한다.
복본 삭제 시 대출 기록 CASCADE명세의 "서적 제거"를 그대로 구현하고, 마지막 복본이 사라지면 서적까지 정리된다.삭제된 복본의 과거 대출 기록도 사라지고 지난 차트 집계에서 빠진다. 대출 중인 복본은 삭제를 거부한다. 이력 보존이 필요해지면 status = 'retired' 같은 논리 삭제로 바꿀 수 있다.
user_id 자연키로그인 ID를 바꾸는 기능이 없어 키가 안정적이고, 외래키 값만으로 회원을 알아볼 수 있다.정수 대리키보다 비교 비용이 크지만 이 규모에서는 무시할 수 있다. 형식을 CHECK로 제한해 화면 출력 시에도 안전하다.
리뷰 자격을 애플리케이션에서 검사"대출 이력이 있는 회원만 리뷰 가능"을 별도 테이블 없이 기존 Loan으로 판단한다.FK나 CHECK로는 다른 테이블의 이력을 조건으로 걸 수 없으므로, 리뷰 작성 요청마다 트랜잭션 안에서 확인한다.
